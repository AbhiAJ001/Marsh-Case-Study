Request Lifecycle
1

User Input

Advisor enters a company name and selects one or more policy documents from the four available options. Clicks Generate.

input_form.py → (company_name: str, policies: list[str])
2

Company Research

Gemini LLM researches the company — industry, employee count, headquarters, key business risks, and health insurance needs. Unverified data is marked with [Assumed] labels.

company_profile.py → CompanyProfile { industry, size, risks, needs }
3

Policy Retrieval (RAG)

Company risks and needs are used as queries against the FAISS vector index. Top 8-10 most relevant policy chunks are retrieved, each tagged with source document, page, and section type.

retriever.py → list[RetrievalResult] with similarity scores
4

Pitch Generation

Company profile + retrieved policy chunks are fed to Gemini with grounding instructions. LLM produces structured 3-5 slide content with explicit source references for each claim.

pitch_generator.py → PitchDeck { slides[], recommended_policy }
5

Content Audit

Each factual claim in the pitch is extracted and cross-referenced against the raw policy documents. Claims are classified as verified (source found), partially supported, or unverifiable (flagged for human review).

audit_engine.py → AuditReport { confidence: 0.87, claims[] }
6

Output Delivery

Pitch is rendered as readable slides. PowerPoint file is generated for download. Audit report shows per-claim status with source citations. Advisor can approve, edit, or reject the pitch.

pptx_builder.py → .pptx | audit_panel.py → approve/edit/reject

AI Usage & Agentic Development Practices

Responsible AI Practices

  • RAG grounding — all claims traced to source policy documents
  • Hallucination detection via audit engine with confidence scoring
  • Assumptions explicitly labelled — never presented as fact
  • Human-in-the-loop — advisor must approve, edit, or reject every pitch
  • Centralized prompt management — versioned, auditable prompts
  • No secrets in code — API keys via environment variables only

Agentic Development Workflow

  • Persistent memory system — mind.md as project context for AI agents
  • Structured task tracking — log.md with phase/task/status/output
  • System blueprint — map.md with full file-to-function reference
  • Decision logging — every tech choice recorded with rationale
  • Modular architecture — each component independently testable
  • Separation of concerns — UI, logic, RAG, and audit are isolated layers

RAG Best Practices

  • Semantic chunking — split by document structure, not character count
  • Rich metadata — source file, page number, section type per chunk
  • Source attribution — every retrieval result carries provenance
  • Configurable top-k — tunable retrieval depth for precision vs recall
  • Persistent vector store — FAISS index saved to disk, not rebuilt each run
  • Multi-document support — retrieval spans all selected policies

Production Quality Signals

  • Graceful error handling — meaningful messages, not stack traces
  • Input validation — company name and policy selection enforced
  • Progressive loading states — stage labels during generation
  • Structured data models — dataclasses for all internal interfaces
  • Clean code — docstrings, type hints, organized imports
  • Anti-AI design — UI deliberately crafted to feel human-made
